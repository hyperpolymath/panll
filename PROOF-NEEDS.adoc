= Proof needs — PanLL
:toc: macro

What PanLL proves today, what it deliberately does not, and what is still
owed. Escape hatches and their dispositions are tracked separately in
link:docs/proof-debt.adoc[`docs/proof-debt.adoc`].

Last reconciled against the tree: 2026-11-09 (`main` at `7d1feaa`).

The policy is hyperpolymath/standards `3-practice/PROOF-POLICY.adoc`.
Statuses in this file use its closed §5 vocabulary: `PROVEN`, `TESTED`,
`ASSUMED`, `OPEN`. Anything else said about an item is in a separate
note, never in place of the token.

== Policy class

Every obligation PanLL owns is an *engineering* obligation (PROOF-POLICY §1):

* interface and ABI contracts (types, layouts, tags, grade contracts) in
  *Idris2*;
* first-party Rust in *Creusot* with *Pearlite* contracts, and *Verus*
  (§1.2);
* Rust `unsafe` blocks and FFI seams additionally in *Kani*, reported as
  `TESTED` with its bounds (§4.1).

PanLL owns no theory theorem, so Proof Witness Grades do not apply here
(§8.1): no `PWG` is stated or owed. The laws of the grade algebras that
`Grades.idr` uses (occupancy, loss, max-plus) are theory. Their source of
truth is hyperpolymath/resource-algebra's Agda, and any grade for them is
recorded there. PanLL uses typed-wasm's Idris2 transcription of them as a
checked dependency (the import cone below); whether that transcription
states the same laws is the open item "Grade kernel identity" (#143).

The Mathesis catalogue (hyperpolymath/mathesis, `docs/catalogue/`) lists
PanLL as an engineering repository whose status document is this file.
Its row comes from the census of 2026-10-26, so it does not yet count the
TLA+ model added since (`docs/models/`); Mathesis derives its rows from
the tree at each census and does not assign them.

== Current state

The only machine-checked proofs live in the panel-clades ABI,
`panel-clades/src/abi/PanelClades/ABI/` (Idris2 0.8.0, `%default total`,
about 1,300 lines). As of the date above, no `.idr` file contains a hole,
`believe_me`, `assert_total`, `assert_smaller`, `idris_crash`,
`unsafePerformIO`, `postulate`, `partial` or `covering`.

The CI job `panel-clades-abi` in `.github/workflows/build-validation.yml`
runs `panel-clades/scripts/check-abi.sh`, which:

* builds typed-wasm's grade kernel at the pin in
  `panel-clades/scripts/fetch-siblings.sh` (`117bbf8`);
* builds `panel-clades/src/abi/panel-clades-grades.ipkg` against it and
  fails on any `Error:` line, even when `idris2` exits 0;
* fails if any module under `PanelClades/` is missing from the ipkg or
  does not declare `%default total` before its first declaration (the
  directive applies only from where it appears), or if its code (comments and string
  literals set aside) contains a hole (`?name`; `idris2 --build` accepts a
  module with holes), `believe_me`, `assert_total`, `assert_smaller`,
  `idris_crash`, `unsafePerformIO`, `postulate`, `partial` or `covering`;
* holds the typed-wasm modules those modules import (the import cone,
  PROOF-POLICY §1.1) to the same scan, and prints the cone;
* fails if `Budgets.idr` is stale against the clade configs
  (`scripts/gen-budgets.sh --check`);
* requires each of the six fixtures in `panel-clades/tests/reject/` to be
  refused at its `invalid` declaration, with the expected message.

=== What is proved

[cols="1,1,3",options="header"]
|===
|Module |Status |Proved

|`Types.idr`
|`PROVEN`
|The C tag encodings of `Result` and `CladeKind` round-trip, so they are
injective (`resultRoundTrip`, `cladeKindRoundTrip`). Equality on both is
decidable without a catch-all `absurd` (`decEqViaTag`). `allCladeKinds`
lists every kind (`cladeKindExhaustive`) and has length `cladeKindCount`.
Each tag is written twice, as a `Nat` for decidable equality and as a
`Bits32` for the C encoding, and the two give the same number
(`resultTagsAgree`, `cladeKindTagsAgree`), so the tables cannot drift
apart. A `Handle` is never null and a `CladeId` is never empty, by
construction.

|`Layout.idr`
|`PROVEN`
|Rounding up to an alignment `a ≥ 1` is tight: the result is a multiple
of `a` (`alignUpCorrect`), at or above the size (`alignUpCovers`) and
below size plus `a` (`alignUpTight`). A computed struct size is a
multiple of its alignment (`calcStructSizeAligned`) and covers every field
(`calcStructSizeCovers`, `fieldWithinEnd`, `fieldWithinStruct`), so
`verifyLayout` has no run-time size check and refuses only an alignment of
0. `CABICompliant` evidence carries every offset as a multiple of its
alignment (`FieldsAligned`), the first field at offset 0, since C allows
no padding before it (`FirstAtZero`), the fields in order with each
starting at or after the previous one's end (`FieldsOrdered`; no two
overlap, since the chain is ordered), every alignment a power of two (`AlignmentsPow2`), and
the struct aligned to its largest field alignment (`maxAlignment`). Each
part is decided by an equation or an `LTE` proof (`decDivides`,
`isLTE`, `decPow2`, `decEq`), not by a Boolean test.

|`Grades.idr`
|`PROVEN`
|Clade resource contracts are graded in typed-wasm's kernel (transcribed
from hyperpolymath/resource-algebra), not re-declared. Occupancy composes
within a bound (`phasesWithin`). Loss adds across two crossings
(`crossTwice`), and the better of two alternatives stays within a shared
bound (`betterOfTwo`). Occupancy and cost are kept apart
(`panelPhasesOccupancy` vs `panelPhasesCost`). The neurosym-bridge
contract typechecks against its declared budget
(`neurosymBridgeContract`). The kernel is in the checked import cone, so
it is not an assumption; whether its definitions match resource-algebra's
is #143.

|===

Two modules carry no obligation and are not in the table.
`Budgets.idr` is generated from the clades' `config.k9.ncl` resource
blocks; it is the input `Grades.idr` checks against. Only neurosym-bridge
declares a budget so far, and the budgets are DESIGNED values, not
measurements. `Foreign.idr` declares the Zig FFI surface and only
typechecks.

The reject fixtures pin down what the types and the decision procedures
refuse: `AlignmentNotPow2`, `BudgetTooSmall`,
`CollapseWithinTolerance`, `MisalignedField`, `NullHandle`, `OverBudget`,
`OverlappingFields`, `StructUnderAligned`
and `WasmPointerIsEightBytes`.

=== What is not proved

These limits are stated in the modules themselves.

* *The decision procedures are complete.* `decDivides`, `decPow2` and
  `checkCABI` are sound: every `Just` or `Right` carries real evidence. A
  `Nothing` or `Left` means only "not shown"; that the property is then
  false is not proved.
* *The Zig side matches.* Nothing checks that `panel-clades/ffi/zig/`
  exports the symbols `Foreign.idr` declares, with those types, or uses
  the sizes and tags `Types.idr` proves. `ffi/zig/src/main.zig` restates
  them by hand.
* *Grades reach the runtime.* The budgets are DESIGNED values from the
  configs, not measurements, and nothing in the panel runtime emits or
  checks these grades yet.

*Idris2 0.8.0* for anything at the ABI or grade level, matching the
existing modules and the typed-wasm kernel they import.

=== TLA+ model of provenance binding

[cols="1,3",options="header"]
|===
|Field |Record

|Artefact
|`docs/models/Provenance.tla`, with three TLC configurations:
`Provenance.cfg` (author key leaked), `ProvenanceWitnessLeak.cfg`
(witness key leaked) and `ProvenanceBothLeak.cfg` (both leaked). They are
run by `scripts/check-provenance-model.sh` in the `provenance-model` job of
`.github/workflows/build-validation.yml`.

|Obligation
|A chain is verified only if it is exactly the genuine chain, in order and
with its genuine content, while at least one of the two signing keys
(author, independent witness) is uncompromised. `Valid` mirrors what
`crates/provenance` `verify_chain` checks: an author signature and a
witness attestation on every record, content matching its digest, and each
record naming its predecessor (the first naming none). The property
`Genuine` refers to the genuine chain, which the verifier never sees, so it
is not `Valid` restated.

|Tool
|TLA+, checked with TLC (`TLC2 Version 2.19 of 08 August 2024`, from
tla2tools v1.7.4)

|Why not the mapped verifier
|The statement is about the protocol, symbolically, with signatures as
sets that only a key holder can add to. The mapped verifiers for the shipped Rust are Creusot /
Pearlite and Verus. They are planned, not yet run: the `verify_entry` /
`verify_witnesses` row above is `OPEN`, and this model does not discharge
it.

|Status
|`TESTED`, with bounds: two field/digest values (`A`, `B`) plus `None`
for the genesis parent, so 12 possible payloads; chains of exactly two
records; any subset of payloads forged under a leaked key. Checked both
ways. With one leaked key, either one, `Genuine` holds over all 591,872
distinct reachable states (depth 13). With both keys leaked, TLC must find
the forgery and does, so the property is not vacuous. Each single-key run
must also exercise its leak: `check-provenance-model.sh` fails unless TLC's
coverage report shows the leaked key's forge action reaching a state and
the other forge action none, so a configuration that leaks no key cannot
pass. A mutation run that
dropped the witness check from `Valid` was caught too: one leaked author
key then forges a chain. Local run on 2026-11-09, about 7 minutes; the
`provenance-model` job's run on `main` is the receipt.

|Assumed
|Signatures cannot be produced without the key (ML-DSA-65 unforgeability),
and the witness attests only genuine records. Timestamps, key
registration, chains longer than two and tail truncation are not modelled.

|Deviation (PROOF-POLICY §6)
|*Leg:* this model check. *Tool:* tla2tools.jar v1.7.4, the
tlaplus/tlaplus GitHub release asset, SHA-256
`936a262061c914694dfd669a543be24573c45d5aa0ff20a8b96b23d01e050e88`; TLC
reports `TLC2 Version 2.19 of 08 August 2024`. *Why:* PanLL has no Guix
manifest or proof container that provides TLC, so the job fetches the
release asset, checks it against the digest pinned in the workflow, and
the script fails on any other TLC version. The digest was taken from the
asset as downloaded over TLS on 2026-11-09; tlaplus publishes no checksum
file to compare it with. Java is the runner image's. *State:* `open`,
until TLC comes from a Guix manifest or a pinned container.
|===

== Priority

. The safe callback wrapper (#149): small and local, and the last gap
  `Foreign.idr` admits to.
. Zig/Idris FFI agreement check: cheap, and it removes the largest
  unchecked assumption under the proofs.
. PCC soundness: the highest-value proof, but only after the AffineScript
  port (#148) gives it something to check.
. The provenance implementation proofs (Creusot / Pearlite and Verus on
  `verify_entry`, `verify_witnesses`, `verify_chain`): the TLA+ model now
  says what the protocol is worth, but not that the Rust implements it.
