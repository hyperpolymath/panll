== What PanLL Is

PanLL is an **eNSAID** — Environment for NeSy-Agentic Integrated Development.

It is a three-pane neurosymbolic workbench for **design, develop, do, and evaluate** workflows across programming languages, databases, and protocols. Each pane serves a distinct cognitive role:

[cols="1,2,3"]
|===
| Pane | Role | Grounded In

| **Pane-L** (Symbolic Mass)
| Constraints, properties, formal guarantees
| proven Safe* types, protocol-squisher compatibility classes, contractiles Mustfile/Trustfile contracts

| **Pane-N** (Neural Stream)
| Agent reasoning, proof search, inference
| ECHIDNA theorem prover (30 backends), hypatia rule engine, gitbot-fleet orchestration

| **Pane-W** (World / Barycentre)
| Verified results, event chains, system state
| panic-attack assault reports, reposystem graph + plans, VeriSimDB hexad queries, stapeln stack designs
|===

PanLL is **not** a generic IDE, framework, or platform. It is a personal neurosymbolic workbench — a multi-monitor trader desk with formal verification behind each panel. It is modular: each integration is a pane module that can be added, removed, or replaced independently.

**Primary focus areas:** Programming Languages, Databases, Protocols. +
**Secondary (later panes):** Containers, Networks, Servers. +
**Persistence backbone:** VeriSimDB (octad hexads store all constraints, traces, and event chains). +
**Core architecture benefit:** The three-pane model and its wiring are useful to _all_ module domains — the eNSAID serves the integrations, not the other way around.

== Current Status: v0.1.0 (2026-02-28) — 92% Complete

=== What Works

* Custom TEA runtime (Model-Update-View) — 8 files, deterministic state transitions
* 31 ReScript source files (3400+ LOC), 1347-line Rust backend (27 functions)
* 109 tests passing (97 Deno.test + 16 Rust, 87-91% coverage)
* Three panes render, persist (localStorage), respond to keyboard shortcuts (Ctrl+Shift+L/N/B/W)
* Anti-Crash circuit breaker gates neural tokens through symbolic validation
* Vexometer tracks cognitive load (cancellations/corrections with exponential decay)
* OrbitalSync detects pane drift via hash-based change monitoring
* Contractiles enforces adaptive state contracts (Strict/Warn/Adaptive)
* panic-attack integration: binary discovery, capability probe, ambush execution, event-chain import (file + paste)
* VeriSimDB: 8 Tauri commands wired (health, VQL query, list/get hexads, drift, normalise, telemetry, orch status)
* ARIA accessibility across all components
* Tailwind CSS 4.x + Deno build pipeline + Tauri 2.0 desktop app

=== What Does Not Work Yet

* VeriSimDB is a query proxy only — no persistence of PanLL state to hexads
* Pane-L constraints are local text entries, not connected to proven or protocol-squisher
* Pane-N inference is validate-only, not connected to ECHIDNA or any reasoning backend
* Pane-W shows panic-attack event chains only — no reposystem, no gitbot-fleet, no stapeln
* No settings UI, no error boundaries, no loading states

== Roadmap

=== v0.2.0 — Connected Workbench (MVP)

**Goal:** PanLL becomes a daily-use tool by connecting to real data sources. The three panes stop being standalone and start reflecting the actual state of work.

==== Must Have

===== Reposystem event chain in Pane-W
* Import reposystem `graph.json` as ecosystem view (400+ repos, dependencies, health scores)
* Display reposystem plan operations as event chains (scan → plan → dispatch → execute)
* Wire `reposystem` Rust library or JSON export as a second event-chain source alongside panic-attack
* Rationale: Git and CI/CD are the backbone of every session. PanLL should show the ecosystem on startup.

===== VeriSimDB as persistence layer
* Store event chains as octad hexads (Document + Temporal + Provenance modalities)
* Store Pane-L constraint sets as hexads (Semantic + Graph modalities)
* Store reasoning traces as hexads (Temporal modality for replay)
* Replace localStorage with VeriSimDB-backed persistence (localStorage as offline fallback)
* Rationale: Without persistence, every session starts from zero. VeriSimDB gives PanLL memory.

===== Protocol-squisher constraints in Pane-L
* Import protocol-squisher IR analysis results as Pane-L constraints
* Display transport class compatibility (Concorde/Business/Economy/Wheelbarrow) between formats
* Query protocol-squisher for adapter cost when designing systems
* Rationale: Protocol compatibility is a constraint problem — Pane-L is where constraints live.

===== Settings and error handling
* Basic settings panel (VeriSimDB URL, panic-attack binary path, reposystem graph path)
* Error boundary handling for failed Tauri commands
* Loading states for async operations (VeriSimDB queries, panic-attack invocations)

==== Should Have

* Error boundary handling with graceful fallback
* Loading states and transition indicators
* Theme support (dark/light, follows system)

==== Could Have

* Onboarding tutorial (first-run walkthrough of three panes)

=== v0.3.0 — Neurosymbolic Core

**Goal:** The "NeSy" in eNSAID becomes real. Pane-N sends proof obligations to ECHIDNA and gets back trust-scored results. Pane-L draws constraints from proven's formally verified catalog.

==== Must Have

===== ECHIDNA as Pane-N reasoning backend
* Wire ECHIDNA's GraphQL API (port 8080) as the reasoning backend for Pane-N
* Send proof obligations from Pane-L constraints → ECHIDNA → results in Pane-W
* Display trust scores (ECHIDNA's 5-level hierarchy) and axiom usage warnings
* Support portfolio solving: multiple provers run in parallel, best result wins
* Rationale: ECHIDNA has 30 working prover backends with trust hardening. This is not research — it is wiring.

===== proven as Pane-L constraint library
* Import proven's 104 Safe* module catalog as selectable Pane-L constraints
* Each constraint is a formally verified property (e.g., "SafeNetwork.IPv4: no invalid octets possible")
* When a constraint is selected, Pane-N can anchor reasoning on it (proof already exists, no need to re-prove)
* Rationale: proven modules are the highest-quality constraints in the ecosystem — dependent types with compile-time proofs.

===== Hypatia findings pipeline
* Consume hypatia scan findings from VeriSimDB (stored as hexads by the CI/CD pipeline)
* Display cross-repo patterns in Pane-W (hotspots, severity distributions, temporal trends)
* Allow Pane-L constraint creation from hypatia findings ("never allow this pattern again")
* Rationale: Closes the loop — CI/CD findings flow into the workbench for analysis and constraint creation.

===== gitbot-fleet status in Pane-W
* Display fleet status: which bots are running, what they found, what rules they propose
* Show the learning loop (observed patterns → threshold → proposed Logtalk rules)
* Allow approval/rejection of proposed rules from Pane-W
* Rationale: Bot orchestration is a core part of the development workflow — it belongs in the workbench.

===== Pane module interface contract
* Extract the common pattern from existing pane modules (panic-attack, VeriSimDB, reposystem, protocol-squisher) into a documented contract
* Define what every pane module must provide: a Tauri command (Rust), a message type (ReScript), an update handler, a view function, and a VeriSimDB hexad schema
* Publish as typed ReScript interface + Rust trait — not a tool yet, just the specification
* Rationale: By v0.3.0 there are 6+ working modules. That is enough to extract the real pattern from facts, not assumptions. This contract is the foundation for the Pane Studio in v0.5.0.

==== Should Have

* Reasoning trace visualization (show which prover solved what, with what axioms)
* Performance monitoring for ECHIDNA queries (latency, prover selection)
* Pane-N agency indicator (shows when inference is active vs. idle)

==== Could Have

* Interactive proof explorer (drill into ECHIDNA proof trees)
* Custom constraint expression language (beyond selecting from proven catalog)

=== v0.4.0 — Holistic Tool Integration

**Goal:** PanLL covers the full stack — languages, databases, protocols, containers, networks. Each domain is a pane module; the three-pane architecture stays constant.

==== Must Have

===== stapeln container integration (Pane-W module)
* Query stapeln's REST/GraphQL API for stack designs and validation results
* Display container security scores and gap analysis findings in Pane-W
* Validate designs against proven constraints (SafeNetwork for ports, SafeDocker for image refs)
* Export verified designs to docker-compose from Pane-W
* Rationale: Container design is a verification problem. PanLL adds the formal layer stapeln lacks.

===== Multi-agent coordination (Pane-N)
* Orchestrate tool chains: panic-attack scans → echidnabot verifies → sustainabot evaluates → glambot formats
* Display agent coordination in Pane-N (which agent is active, what it decided, why)
* Wire gitbot-fleet's shared-context API for inter-agent state
* Rationale: The "Agentic" in eNSAID. Not abstract agent frameworks — concrete bot orchestration.

===== Eclexia as language playground (Pane-L module)
* Import Eclexia syntax/type definitions as Pane-L constraints for language design
* Display type system properties and validate new constructs against them
* Rationale: Language design is constraint-driven. Pane-L is the right place for it.

==== Should Have

* Network analysis module (start with panic-attack ambush against proven-bgp)
* proven-bgp as first "server under test" in Pane-W (BGP FSM state visualization)

==== Could Have

* airie network simulation tool (create when network testing needs outgrow panic-attack ambush)

=== v0.5.0 — Development Workflows

**Goal:** PanLL becomes the command center for multi-repo development operations. Design, develop, do, evaluate — all through the three panes.

==== Must Have

===== VQL/protocol REPL in Pane-L
* Type VQL queries directly in Pane-L, see results in Pane-W, reasoning trace in Pane-N
* Protocol-squisher queries inline (analyze a schema, get compatibility report)
* Rationale: The REPL is where "design" and "evaluate" happen interactively.

===== Reposystem plan execution
* Design multi-repo changes in PanLL (select repos from graph, define operations)
* Dispatch via git-dispatcher, watch gitbot-fleet execute in Pane-W
* Dustfile rollback available if execution fails
* Rationale: Multi-repo orchestration through the workbench, not through shell scripts.

===== contractiles enforcement
* Display Mustfile/Trustfile/Dustfile/Intentfile contracts in Pane-L
* Verify contract satisfaction in Pane-W (green/amber/red status per contract)
* Alert on contract violations before operations execute
* Rationale: Contractiles is the operational safety layer — it belongs in the constraint pane.

===== claim-forge integration
* Timestamp designs and verified results via claim-forge (GPG + OpenTimestamps)
* Attach provenance records to VeriSimDB hexads
* Rationale: IP protection for work created in PanLL.

===== Pane Studio (scaffoldia profile)
* Build a pane module scaffolder that generates all artifacts for a new module: ReScript component, Tauri command, message types, update handler, VeriSimDB hexad schema, and test stubs
* Implemented as a scaffoldia profile — not a separate tool. `scaffoldia generate --profile panll-pane --name my-module` produces a working module skeleton that compiles and renders immediately.
* Uses the pane module interface contract (defined in v0.3.0) as the generation target
* Includes MiniKanren constraints from scaffoldia to validate module structure (e.g., "every module that writes to Pane-W must define at least one event-chain parser")
* Rationale: By v0.5.0, 8+ modules have been built by hand. The pattern is proven. Scaffoldia already solves composable template generation — a PanLL profile is a natural extension, not a new tool. This becomes the plugin system foundation for v1.0.0.

==== Should Have

* Scaffoldia integration (generate new repo structures from Pane-W)
* Code navigation for files referenced in event chains and findings

==== Could Have

* Visual diff for reposystem plan operations (before/after preview)

=== v1.0.0 — Production eNSAID

**Goal:** Stable, documented, daily-driver quality. The tool you use for everything.

==== Must Have

* Stable pane module API (no breaking changes to module interface)
* Comprehensive documentation (architecture guide, module development guide, user guide)
* Security audit (panic-attack self-scan + ECHIDNA verification of critical paths)
* All pane modules have integration tests against real backends
* Test coverage 95%+
* Performance profiling and optimization (startup < 2s, query response < 500ms)

==== Should Have

* Plugin system for third-party pane modules (built on Pane Studio from v0.5.0 — third parties run `scaffoldia generate --profile panll-pane` and get a working module skeleton)
* Multi-platform builds (Linux primary, macOS, Windows via Tauri)
* Headless mode for CI/CD integration (constraint check + ECHIDNA verification as pipeline gate)

==== Could Have

* BEAM backend for distributed PanLL instances sharing VeriSimDB state
* Web-based version (Tauri webview extracted to standalone)

== Post-v1.0

=== Near-Term

* **More proven apps as test targets** — proven-httpd, proven-dns, proven-quic become servers PanLL can exercise
* **PanLL as CI/CD gate** — Run headless in pipelines: "do these changes satisfy Pane-L constraints?"
* **Distributed instances** — Multiple PanLL workbenches sharing VeriSimDB state via the BEAM orchestration layer

=== Long-Term

* **Academic publication** — The three-pane neurosymbolic model (Binary Star architecture) as a research contribution
* **Community pane modules** — Others write modules for their own tools/databases/protocols
