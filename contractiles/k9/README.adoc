== Overview

K9 is the Nickel-based validation and recipe system within the
https://github.com/hyperpolymath/reposystem[contractile CLI]. It provides
two levels of operation:

Yard (read-only)::
  Validators that declare structural contracts. They describe what a valid
  artifact looks like without executing any commands or modifying any files.
  Evaluated via `k9 eval` or `k9 typecheck`.

Hunt (executable)::
  Recipes that execute commands with real side effects (build, scaffold,
  audit). Every Hunt recipe requires `signature_required = true` and
  declares its `side_effects` explicitly. Executed via `k9 run`.

== Validators (Yard Level)

Validators are pure data contracts. They define the shape of valid
artifacts and compute boolean flags indicating compliance. The K9 runner
populates detection fields (e.g. `has_aria_labels`, `violations_found`)
and the validator computes the result fields (e.g. `meets_baseline`,
`is_clean`).

=== panel-structure.k9.ncl

Validates the DD-004 8-file pattern for panels. Every panel needs 4 core
ReScript files (model, engine, component, test). Backend panels add 4
more (cmd, rust mod, rust types, rust commands).

=== wiring-completeness.k9.ncl

Validates all 7 PCC wiring points: registry entry, model include, msg
namespace, view route, update handler, rust registration, and init
subscription. Reports a `wired_count` for progress tracking.

=== clade-integrity.k9.ncl

Validates clade manifest structure including kind, parent, traits, and
consistency rules (e.g. overlay panels must not have backends, read-only
panels must not claim persistence).

=== tea-purity.k9.ncl

Ensures Engine files contain no side effects. Defines 10 banned patterns
(`invoke(`, `fetch(`, `localStorage`, `console.log`, `window.`,
`document.`, `setTimeout`, `setInterval`, `Promise`, `Math.random`)
and 4 allowed patterns (`Tea_Cmd.none`, `Tea_Cmd.msg`, `Tea_Cmd.batch`,
`Tea_Cmd.call`).

=== accessibility-baseline.k9.ncl

Validates WCAG accessibility baseline per DD-008. Checks for ARIA labels,
role attributes, keyboard handlers, and tab index. Defines both a minimum
baseline and full compliance levels.

=== spdx-compliance.k9.ncl

Validates SPDX license headers. Enforces PMPL-1.0-or-later for original
code, allows MPL-2.0 as platform fallback, and permits standard OSI
licenses for third-party dependencies.

=== dangerous-patterns.k9.ncl

Validates that source files contain no banned escape-hatch patterns.
Covers 5 languages (ReScript, Rust, Idris2, OCaml, Haskell) with
language-specific banned pattern sets.

=== provenance-chain.k9.ncl

Validates code provenance per DD-006. Assigns trust levels (verified,
human_reviewed, ai_assisted, unreviewed_ai, unknown) and enforces the
hostile UX policy for unreviewed AI code.

== Recipes (Hunt Level)

Recipes execute commands and have real side effects. Each recipe includes:

- A `pedigree` block with name, version, author, leash level, and signature requirement
- A `side_effects` declaration (filesystem reads/writes, network, command execution)
- A `recipes` map of named gates, each with command, description, timeout, and expected exit code

=== build-validation.k9.ncl

Runs the full build pipeline in fail-fast mode:

1. `deno task res:build` -- ReScript compilation
2. `cargo check` -- Rust type checking
3. `panll panel verify` -- PCC wiring verification
4. `deno test` -- Test suite

=== panel-mint.k9.ncl

Scaffolds and wires a new panel. Parameters: `panel_name` (PascalCase),
`clade_kind`, `has_backend`, `parent_clade`. Creates all DD-004 files,
wires all PCC points, and runs verification.

=== seam-audit.k9.ncl

Runs proximal and distal seam checks in collect-all mode (no fail-fast).
Proximal: invoke parity, wiring consistency, message routing, style
imports. Distal: TypeLL compatibility, VeriSimDB interface, ECHIDNA
integration.

=== release-gate.k9.ncl

Phase 4 release readiness with 10 gates in collect-all mode. Covers
build, tests, seams, SPDX, dangerous patterns, accessibility,
provenance, panic-attack security scan, changelog, and version
consistency.

== Usage

[source,bash]
----
# Typecheck a validator (no execution)
k9 typecheck validators/panel-structure.k9.ncl

# Evaluate a validator with data
k9 eval validators/tea-purity.k9.ncl --data '{"engine_file": "src/core/FileExplorerEngine.res"}'

# Run a Hunt recipe (requires signature)
k9 run recipes/build-validation.k9.ncl

# Mint a new panel
k9 run recipes/panel-mint.k9.ncl \
  --param panel_name=FileExplorer \
  --param clade_kind=builder \
  --param has_backend=true

# Full release gate
k9 run recipes/release-gate.k9.ncl --param version=0.5.0

# Get info about a K9 file
k9 info validators/clade-integrity.k9.ncl
----

== Naming Convention

All K9 files use the `.k9.ncl` double extension:

- `.k9` identifies the file as part of the K9 system
- `.ncl` identifies the file as valid Nickel for editor tooling

== Signature Verification

Hunt recipes require OpenSSL signature verification before execution.
The K9 runner checks for a `.sig` file alongside each recipe:

[source]
----
recipes/build-validation.k9.ncl      # The recipe
recipes/build-validation.k9.ncl.sig  # Its signature
----

Generate a signature:

[source,bash]
----
openssl dgst -sha256 -sign private.pem -out recipe.k9.ncl.sig recipe.k9.ncl
----
