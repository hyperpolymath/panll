= PanLL Wizard Standards
:toc:
:toclevels: 4

== Overview

The PanLL Wizard provides a guided, validated workflow for creating plugins and panels while maintaining compliance with PanLL architectural standards and governance requirements.

== Architecture

=== Design Principles

1. **Guided Creation**: Step-by-step process with clear progression
2. **Validation-First**: Immediate feedback on configuration choices
3. **Template-Driven**: Pre-configured starting points for common use cases
4. **Governance-Compliant**: Built-in contractile and Groove protocol support
5. **Accessibility-First**: WCAG 2.3 compliance by default

=== Component Diagram

[source,mermaid]
----
flowchart TD
    A[Wizard UI] -->|User Actions| B[UpdateWizard]
    B -->|State Updates| C[WizardModel]
    B -->|Commands| D[WizardCmd]
    D -->|Backend Calls| E[Minter Service]
    E -->|Generation| F[File System]
    E -->|Registration| G[Panel Registry]
    C -->|Validation| H[Validation Rules]
    C -->|Templates| I[Template Registry]
----

== Wizard Steps

=== 1. Select Type

*Choose between creating a Panel or Plugin*

[cols="1,3"]
|===
| Option | Description

| CreatingPanel
| Full-featured UI component with backend integration

| CreatingPlugin
| Reusable functionality module with limited UI
|===

=== 2. Choose Capabilities

*Select from available capabilities with real-time validation*

[cols="1,2,1"]
|===
| Capability | Description | Category

| groove-soft
| Optional Groove protocol integration
| Protocol

| groove-hard
| Required Groove protocol integration  
| Protocol

| contractile
| Contractile governance support
| Governance

| accessibility
| WCAG 2.3 compliance features
| UX

| minter
| Panel creation capabilities
| Core

| provisioner
| Dependency management
| Core
|===

=== 3. Configure Dependencies

*Add and manage plugin dependencies with version control*

[source,json]
----
{
  "dependencies": [
    {
      "pluginId": "groove-core",
      "version": "1.0.0",
      "trustTier": "Trusted"
    }
  ]
}
----

=== 4. Setup Security

*Configure sandboxing and permissions*

[cols="1,3,1"]
|===
| Setting | Options | Default

| Trust Tier
| Ayo, Trusted, HighAssurance, Governance
| Ayo

| Network Access
| Enabled/Disabled
| Disabled

| Filesystem Access
| Enabled/Disabled
| Disabled

| Sandbox Policy
| Custom capability allowlist
| Empty (deny all)
|===

=== 5. Review & Generate

*Final validation and generation*

[source,json]
----
{
  "type": "panel",
  "capabilities": ["accessibility", "groove-soft"],
  "dependencies": [{"id": "groove-core", "version": "1.0.0"}],
  "security": {
    "trustTier": "Trusted",
    "networkAccess": false,
    "filesystemAccess": false
  }
}
----

== Validation System

=== Real-Time Validation Rules

[cols="1,2,1"]
|===
| Rule Type | Description | Example

| Capability Conflict
| Prevents incompatible capabilities
| groove-hard + groove-soft

| Dependency Validation
| Checks for duplicates and validity
| Duplicate plugin IDs

| Security Policy
| Enforces trust tier permissions
| Ayo tier with network access

| Template Validation
| Ensures templates are valid
| Missing required fields
|===

=== Validation Workflow

[source,mermaid]
----
flowchart TD
    A[User Action] --> B[Client-Side Validation]
    B -->|Valid| C[Apply Change]
    B -->|Invalid| D[Show Error]
    C --> E[Backend Validation]
    E -->|Valid| F[Success]
    E -->|Invalid| D[Show Error]
----

=== Optimization Strategies

1. **Memoization**: Cache validation results
2. **Debouncing**: Limit validation frequency during rapid input
3. **Lazy Loading**: Load templates on-demand
4. **Batch Processing**: Group backend validation requests

== Appendix

=== Glossary

*Wizard*:: Guided creation interface for plugins and panels
*Template*:: Pre-configured set of capabilities, dependencies, and settings
*Groove Protocol*:: PanLL's service discovery and communication protocol
*Contractile*:: Governance and compliance framework
*Minter*:: Component generation and scaffolding system
